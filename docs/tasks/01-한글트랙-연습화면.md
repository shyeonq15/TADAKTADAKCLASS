# 작업 01 · 한글 트랙 연습 화면 만들기

> 이 문서는 선생님이 클로드 앱에서 정리해 넘긴 작업 지시서입니다.
> 시작 전에 `CLAUDE.md`(특히 3-2, 3-2-2, 3-2-3, 6장, 7장), `DESIGN.md`의 `TypingArea`·`StatCard`·`PixelProgressBar`·`TierBadge`, 그리고 `AGENTS.md`(Next.js 16 안내)를 읽으세요.

> ⚠️ **수정 안내 (먼저 읽기)**
> 이 지시서는 예전 저장소 사본을 보고 쓴 것이라, 이미 있는 코드와 겹치는 부분이 있습니다. 아래가 우선합니다.
> - **새로 만들지 말고 기존 코드를 쓴다**: 타자 엔진은 `src/lib/typing/`(engine.ts, hangul.ts, integrity.ts), 연습 화면은 `src/app/(student)/practice/[track]/[level]/`, 연습팩은 `src/data/packs/index.ts`의 `Pack`/`Level` 구조
> - 아래 3단계(타자 엔진)는 **새로 만들지 않는다**. 대신 기존 엔진의 타수 계산이 `korean-track.json`의 `keystrokes` 규칙(겹모음·겹받침 2타, 쌍자음 1타)과 같은지만 확인하고 다르면 알려 준다
> - 4단계 화면은 `/practice/korean` 새 경로 대신 **기존 연습 화면과 TrackMap**에 6티어 × 5단계를 연결한다. `korean-track.json`을 기존 `korean.json` 대신 쓰도록 `packs/index.ts`를 바꾸거나, 변환 함수로 `Level` 30개를 만든다 (어느 쪽이 나은지 판단해서 진행)
> - 로그인·기록 저장이 이미 있으므로 "저장하지 않는다"는 무시하고 기존 흐름을 그대로 쓴다
> - 영타·기호·코드는 아직 예전 레벨 구조를 쓰므로, 티어 구조로 바꿀 때 **네 트랙이 같이 쓸 수 있게** 만든다

## 목표

선생님이 `http://localhost:3000/practice/korean` 에서 한글 트랙을 티어·단계별로 직접 쳐 보고, **한 판 분량(약 2분)이 적당한지** 확인할 수 있게 한다.
로그인, 저장, 점수 기록은 이번 작업에 넣지 않는다. 모든 티어와 단계를 잠그지 않고 열어 둔다.

## 할 일 (순서대로, 하나 끝날 때마다 확인)

### 1. `src/config/game.ts`를 새 티어 규칙으로 바꾸기
- 티어 6개: `bronze, silver, gold, diamond, master, legend` (이름·아이콘은 CLAUDE.md 3-2 표)
- 트랙별 목표 타수 범위와 정확도를 CLAUDE.md 3-2 표 그대로 넣고, 단계 목표는 범위를 5등분해 반올림 (한글 브론즈 40·50·60·70·80)
- 단계 통과: 목표 타수와 정확도를 **1번** 넘으면 통과. 티어 하락 없음
- 한 판 분량 `ROUND_SIZE`: 브론즈 4 · 실버 15 · 골드 5 · 다이아 4 · 마스터 2 · 레전드 1
- 특별 칭호 `</>` 코드 마스터: 코드 트랙 다이아 달성
- 예전 `TIER_MIN_CPM`, `TIER_RULES.recordsToPromote: 3`, `minAccuracy: 95`는 지우고, 쓰던 곳이 있으면 함께 고친다
- JSON의 `targetTpm`·`accuracy`와 game.ts 값이 같은지 확인하는 작은 검사 함수(또는 테스트)를 둔다

### 2. 연습팩 불러오기
- `src/data/packs/types.ts`에 위 JSON 구조의 타입
- `src/lib/packs.ts`에 `getTrack('korean')`, `getStage(tierId, stage)`
- `src/lib/typing/round.ts`에 `pickRound(passages, count)` : 같은 판 안에서 중복 없이 무작위로 뽑는 순수 함수

### 3. 타자 엔진 `src/lib/typing/` (화면과 분리된 순수 TypeScript)
- 한글 조합 중(`compositionstart`~`compositionend`) 글자는 오타로 판정하지 않는다
- 타수는 **자모 키 입력 기준**으로 JSON과 같은 규칙: 겹모음(ㅘ ㅙ ㅚ ㅝ ㅞ ㅟ ㅢ)·겹받침은 2타, 쌍자음과 ㅒ ㅖ는 1타(Shift 따로 셈), 띄어쓰기·문장부호 1타
  - 확인용: `"이진수는 0과 1만을 사용하는 수 체계이다."` 는 JSON에 `keystrokes` 값이 있으니, 엔진 계산값과 같아야 한다
- 타수 = 친 타수 ÷ 걸린 분, 정확도 = 맞은 글자 ÷ 전체 글자
- 붙여넣기 차단 (`paste`, `drop`, 오른쪽 클릭 메뉴)
- 한글 지문인데 영문이 들어오면 "한/영 키를 확인하세요" 안내

### 4. 화면 `src/app/practice/korean/`
- 티어 6개 × 단계 5개 선택 화면 (`TierBadge` + 단계 숫자). 단계마다 목표 타수, 정확도, 지문 수 표시
- 한 판 화면: `TypingArea` 하나에 지문을 차례로 보여 줌. 위쪽에 실시간 타수·정확도·진행률(`PixelProgressBar`)
- DESIGN.md 규칙: 타자 영역은 장식·애니메이션·주사선 없음, D2Coding, 오타는 빨간색 + 밑줄
- 결과 화면: 한 판 평균 타수, 정확도, 걸린 시간, 목표 통과 여부, 자주 틀린 글자. "다시 하기"(새로 무작위 뽑기)와 "다른 단계" 버튼
- 결과는 저장하지 않는다 (나중에 Supabase 작업에서 붙임)

### 5. 확인
- `npm run lint`, `npm run build` 오류 없음
- 선생님에게 확인 방법을 쉽게 안내: `npm run dev` → `http://localhost:3000/practice/korean` → 각 티어 1단계와 5단계를 한 판씩 쳐 보고, 한 판이 2분 안팎인지 확인
- 한 판 분량을 바꾸고 싶으면 `src/config/game.ts`의 `ROUND_SIZE` 숫자만 바꾸면 된다는 것도 알려 주기

## 하지 말 것
- `korean-track.json`의 지문을 손으로 고치거나 지우지 않는다 (지문 수정은 검토표로 받아서 다시 생성)
- 로그인, 데이터베이스, 점수 저장은 이번 작업 범위가 아니다
- 영타·기호·코드 트랙 화면은 만들지 않는다. 다만 `getTrack(track)`처럼 트랙 이름만 바꾸면 쓸 수 있게 만든다
