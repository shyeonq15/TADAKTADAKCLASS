# 타닥타닥 우리반 PRD

Oct 24, 2026 · @현

## 1. 개요

**한 줄 정의**: 중학생이 수업 전 5\~10분 동안 한글·영타·코딩 기호를 연습하고, 그 성장을 개인·반 단위로 확인하며 대결하는 웹 타자 게임 플랫폼이다.

**서비스 이름**: 타닥타닥 우리반 (확정)

### 배경

- 고등학교에 올라가면 텍스트 코딩(파이썬 등)을 해야 하지만, 학생들이 `( ) [ ] { } : ; " ' = _ #` 같은 기호와 영타에 익숙하지 않다.
- 한글 타자부터 어려운 학생도 많다.
- 기존 타자 게임은 빠른 학생만 계속 이기는 구조라, 느린 학생은 쉽게 흥미를 잃는다.

### 목표

1. 수업 시작 전 5\~10분 연습을 습관으로 만든다.
2. 학기 말까지 학생이 한글 → 영타 → 기호 → 코드 따라치기까지 도달하게 한다.
3. 속도가 아닌 **성장**을 보상해서, 하위권 학생도 반에 기여하는 경험을 준다.
4. 잘하는 학생에게도 실력에 맞는 도전과 명예를 준다.
5. 교사가 교과서 내용으로 연습문을 쉽게 만들고, 학생 성장을 한눈에 본다.

### 비목표 (1차에서 하지 않는 것)

- 학교 밖 일반 공개 서비스 운영 (파일럿 검증 후 결정)
- 학생 간 자유 채팅
- 모바일·태블릿 최적화 (학교 PC실 기준)
- 다른 학교와의 리그

## 2. 대상 사용자와 사용 환경

1차 파일럿은 **1학년 6개 반(약 180명)과 정보 교사 1명**이 대상이며, 학교 PC실에서 학교 구글 계정으로 사용한다.

| 사용자 | 하는 일 | 핵심 니즈 |
| --- | --- | --- |
| 학생 (하위권) | 자리연습, 한글·영타 기초 | 부담 없이 시작, 작은 성장도 인정받기 |
| 학생 (중위권) | 기호·코드 연습, 대결 | 재미, 반에 기여하는 느낌 |
| 학생 (상위권) | 고난도 지문, 대결, 보스전 | 실력 인정, 도전거리, 명예 |
| 교사 | 연습문 지정, 반 관리, 성장 확인 | 준비 시간 최소화, 한눈에 보는 현황 |

### 사용 환경

- **기기**: 학교 PC실 데스크톱 + 물리 키보드
- **브라우저**: 크롬 기준
- **로그인**: 학교 구글 계정 (학교 도메인만 허용). 학교 계정 로그인이 막혀 있으면 임시로 반 코드 + 번호 + 4자리 PIN 로그인
- **사용 시점**: 수업 시작 전 5\~10분, 정보 시간 중 대결 이벤트

### 확장 계획

- 내년: 학년 확대 (1·2학년 동시 운영, 진급 후에도 기록 유지)
- 이후: 다른 학교·교사에게 공개 검토

## 3. 핵심 컨셉과 설계 원칙

핵심 문장은 **어제의 나보다 성장하면, 반이 함께 강해진다** 이다. 점수를 두 개로 나눠 하위권과 상위권 모두에게 동기를 준다.

| 구분 | 성장 점수 | 실력 티어 |
| --- | --- | --- |
| 기준 | 내 평균 대비 얼마나 늘었나 | 지금 얼마나 잘 치나 |
| 쓰임 | 반 대결, 반 미니룸 화폐 | 개인 칭호, 명예의 전당, 한정 아이템 |
| 유리한 학생 | 모두 공평 | 상위권 |
| 공개 범위 | 반 합산만 크게 표시 | 본인 프로필에 표시 |

### 설계 원칙

1. **성장이 속도보다 중요하다**: 10타 → 60타가 400타 → 410타보다 반에 더 크게 기여한다.
2. **5\~10분 안에 끝난다**: 접속부터 오늘의 미션 완료까지 5분 이내.
3. **비교는 자기 자신과**: 개인 타수 순위는 공개 화면에 띄우지 않는다. 예외는 명예의 전당.
4. **고교 코딩까지 이어진다**: 모든 트랙의 끝은 실제 파이썬 코드 따라치기.
5. **미니홈피 감성**: 반 미니룸 꾸미기, 개인 미니미, 화폐(도토리 같은 재화)로 소속감을 만든다.
6. **안전한 교실**: 자유 채팅 없음, 대결은 수락제, 실명 대신 닉네임.

## 5. 기능 상세 명세

1차 기능은 설명과 완료 기준을 함께 적었다. 완료 기준을 모두 만족해야 그 기능이 끝난 것으로 본다.

### 5-1. 기반 (C)

| ID | 설명 | 완료 기준 |
| --- | --- | --- |
| C1 | 학교 구글 계정으로만 로그인. 첫 로그인 때 교사가 만든 반 코드로 반에 들어가고 닉네임을 정한다. | 학교 도메인 외 계정은 거부된다. 학생 화면 어디에도 실명이 보이지 않는다. 교사 화면에서만 실명과 닉네임이 함께 보인다. |
| C2 | 한글 조합 중 상태를 처리하고, 타수는 자모 기준으로 계산한다. 한/영 상태가 틀리면 안내한다. | 조합 중인 글자를 오타로 판정하지 않는다. 한글 모드에서 영문이 입력되면 "한/영 키를 확인하세요"가 뜬다. |
| C3 | 성장 점수의 기준값을 첫 기록이 아닌 최근 5회 기록의 중앙값으로 잡고, 하루 성장 점수에 상한(50점)을 둔다. | 일부러 느리게 친 기록이 있어도 다음 날 성장 점수가 비정상적으로 커지지 않는다. |
| C4 | 붙여넣기 차단, 사람이 불가능한 속도나 너무 일정한 입력 간격을 감지한다. | 붙여넣기가 동작하지 않는다. 의심 기록은 점수에 반영되지 않고 교사에게 표시된다. |
| C5 | 학교 › 학년도 › 학년 › 반 › 학생 구조로 저장한다. 학생 기록은 학년도가 바뀌어도 학생에게 붙어 있다. | 진급 처리 후에도 이전 학년 기록과 성장 그래프가 이어진다. |
| C6 | 교과서에서 발췌한 초기 연습팩을 플랫폼 형식(JSON)으로 준비해 넣는다. | 4개 트랙 각각 최소 1개 연습팩이 있다. |

### 5-2. 연습 (P)

| ID | 설명 | 완료 기준 |
| --- | --- | --- |
| P1 | 한글 → 영타 → 기호 → 코드 4단계 트랙. 각 트랙은 여러 레벨로 나뉜다. | 학생은 자기 레벨에서 시작하고, 기준을 넘으면 다음 레벨이 열린다. |
| P2 | 자리연습, 단어, 문장, 코드 따라치기 모드. 코드는 들여쓰기를 유지한다. | 네 모드가 모두 동작하고, 코드 모드에서 들여쓰기와 줄바꿈이 원문과 같다. |

| P4 | 치는 동안 타수, 정확도, 진행률을 보여주고 끝나면 결과 화면을 보여준다. | 결과 화면에 타수, 정확도, 내 평균 대비 변화, 자주 틀린 키가 나온다. |
| P5 | 첫 접속 때 짧은 배치 테스트로 시작 레벨을 정한다. | 2분 이내 테스트 후 트랙별 시작 레벨이 정해진다. |

## 6. 점수, 보상, 경제 규칙

아래 숫자는 초기값이며, 파일럿 첫 2주 데이터를 보고 조정한다. 점수·티어·화폐 수치는 코드에서 상수 파일로 분리해 쉽게 바꿀 수 있게 한다.

### 성장 점수 (반 대결용)

- **기준값** = 같은 트랙·레벨에서 **최근 5회 기록의 중앙값** (평균이 아니라 중앙값이라, 일부러 느리게 친 기록에 흔들리지 않는다)
- 기록이 5개 미만이면 배치 테스트 결과를 기준값으로 쓴다.
- 향상은 **%로 계산**한다 (10타 → 12타 = 20% 향상이므로 하위권에게 공평하다).

| 항목 | 계산 | 최대 |
| --- | --- | --- |
| 참여 | 오늘의 미션 완료 | 10점 |
| 속도 향상 | 기준값 대비 1% 오를 때마다 1점 | 15점 |
| 정확도 향상 | 기준값 대비 1%p 오를 때마다 1점 | 5점 |
| 연속 연습 | 연속 일수 × 2점 | 10점 |
| 레벨 첫 클리어 | 1회 | 10점 |

- **정확도 85% 미만이면 속도 향상 점수는 0점**
- **하루 상한 50점**
- **반 점수** = 반 학생 성장 점수 합 ÷ 반 인원
- **집계 주기** = 반 대결은 2주 단위로 집계하고, 2주마다 월요일에 발표한다. 1위 반은 반 지갑 보너스를 받는다.

### 실력 티어 (개인 명예용, 트랙별로 따로)

| 티어 | 한글 (타/분) | 영타 (타/분) | 기호·코드 (타/분) |
| --- | --- | --- | --- |
| 브론즈 | 0\~149 | 0\~99 | 0\~79 |
| 실버 | 150\~249 | 100\~179 | 80\~139 |
| 골드 | 250\~349 | 180\~259 | 140\~199 |
| 다이아 | 350 이상 | 260 이상 | 200 이상 |
| 코드 마스터 | 코드 트랙 다이아 달성 시 주는 특별 칭호 | | |

- 정확도 **95% 이상**인 기록만 인정한다.
- 기준을 넘는 기록이 **3번** 나와야 승급한다.
- 프로필에는 세 트랙 중 **가장 높은 티어**를 표시한다.
- **학기 중 티어 하락은 없다.**
- 기준 숫자는 초안이다. 배치 테스트 후 브론즈 30% · 실버 30% · 골드 25% · 다이아 15% 정도가 되게 조정한다.

### 대결 레이팅 (자동 매치용)

- 체스 랭킹(Elo) 방식: 이기면 오르고 지면 내려간다. 강한 상대를 이기면 더 많이 오른다.
- 성장 모드 결과는 레이팅에 반영하지 않는다.

### 화폐

| 행동 | 개인 지갑 | 반 지갑 |
| --- | --- | --- |
| 오늘의 미션 완료 | 지급 | 지급 |
| 개인 기록 갱신 | 지급 | - |
| 대결 참여 (승패 무관) | 지급 | - |
| 대결 승리 | 추가 지급 | - |
| 보스 격파 | 추가 지급 | 지급 |
| 반 대결 1위 (2주 단위) | - | 보너스 |

- 개인 지갑은 미니미 아이템, 반 지갑은 미니룸 아이템에 쓴다.
- 화폐는 성장 점수에서 직접 바뀌지 않는다. 연습을 많이 하고 꾸준히 하면 모이는 구조다.

## 7. 주요 사용자 흐름

### 7-1. 학생: 첫 접속

1. 학교 구글 계정으로 로그인
2. 교사가 알려준 반 코드 입력 → 반 배정
3. 닉네임 정하기, 기본 미니미 고르기
4. 2분 배치 테스트 → 트랙별 시작 레벨 결정
5. 우리 반 미니룸 화면으로 이동

### 7-2. 학생: 수업 전 5\~10분 루틴

1. 로그인하면 우리 반 미니룸이 첫 화면 (오늘 완료한 친구 미니미가 빛남)
2. "오늘의 미션" 버튼 → 3\~5분 연습
3. 결과 화면: 타수, 정확도, 내 평균 대비 변화, 약한 키
4. 화폐 획득 + 반 성장 게이지가 오르는 연출
5. 남은 시간에 자유 연습, 보스전, 꾸미기

### 7-3. 학생: 대결

1. 대결 메뉴 → 지정 대결(친구 초대) 또는 자동 매치 선택
2. 트랙(한글·영타·기호·코드)과 모드(클래식·성장) 선택
3. 대기실: 상대 미니미와 티어 확인, "준비"
4. 카운트다운 3, 2, 1 → 같은 지문으로 레이스 (30\~60초)
5. 3판 2선승 → 결과 화면: 순위, 타수, 정확도, 평균 대비 %
6. 레이팅 변화와 화폐 지급, 이모티콘 주고받기

### 7-4. 교사: 연습문 만들기

1. 교사 화면 → "연습문 만들기"
2. 교과서 문단이나 코드를 붙여넣기
3. 자동 분할 결과와 난이도·기호 비율 확인, 필요하면 수정
4. 코드면 들여쓰기·주석 옵션 선택
5. 연습팩에 넣고 대상 반·기간·오늘의 미션 여부 지정
6. 학생 화면 미리보기 → 배포

### 7-5. 교사: 수업 시작

1. 교사 대시보드를 TV나 프로젝터에 띄움
2. 반별 "오늘 완료 인원"이 실시간으로 올라감
3. 시간이 되면 미완료 학생 확인 후 수업 시작
4. 필요하면 이상 기록 목록 확인

| 비용 | 파일럿 규모에서는 무료 요금제 범위 안에서 운영하는 것을 목표로 한다. |

## 10. 성공 지표

파일럿 한 학기 동안 아래 지표로 성공 여부를 판단한다. 목표치는 초안이며 선생님 판단으로 조정한다.

| 지표 | 측정 방법 | 목표 (초안) |
| --- | --- | --- |
| 수업 전 연습 참여율 | 정보 수업일 중 오늘의 미션 완료 학생 비율 | 80% 이상 |
| 하위권 성장 | 배치 테스트 하위 30% 학생의 한글 타수 변화 | 학기 말 2배 이상 |
| 기호·코드 도달률 | 기호 트랙 이상 도달한 학생 비율 | 학기 말 70% 이상 |
| 기호 정확도 | 기호 트랙 평균 정확도 변화 | 학기 초 대비 +20%p |
| 상위권 유지 | 배치 테스트 상위 20% 학생의 주간 접속 유지율 | 학기 말까지 80% 이상 |
| 교사 준비 시간 | 연습팩 하나 만드는 데 걸리는 시간 | 5분 이내 |
| 부정행위 | 이상 기록으로 무효 처리된 비율 | 전체 기록의 2% 미만 |
| 학생 만족도 | 학기 말 설문 "수업 전 타자 연습이 재밌다" | 긍정 70% 이상 |
